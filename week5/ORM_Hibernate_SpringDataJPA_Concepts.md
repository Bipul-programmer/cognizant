# ORM, Hibernate & Spring Data JPA Concepts - Week 5

## 1. Need & Benefits of ORM (Object-Relational Mapping)
**ORM (Object-Relational Mapping)** is a programming technique that maps object-oriented code (Java domain classes) to relational database tables (SQL).

### Benefits of ORM:
- **Reduces Boilerplate Code:** Eliminates manual JDBC code (connection management, SQL string manipulation, parsing `ResultSet` objects).
- **Database Abstraction & Portability:** Switches database vendors (e.g., MySQL ➔ PostgreSQL ➔ H2) by simply changing dialect configuration without modifying Java domain logic.
- **Object-Oriented Design:** Allows developers to think in terms of objects, inheritance, relationships (`@OneToMany`, `@ManyToOne`), and domain logic rather than SQL joins.
- **Automated Transactionality & Caching:** Manages database transactions and caches entities (First-level and Second-level cache) for improved performance.

## 2. Evolution of ORM Solutions & Benefits of Spring Data JPA

```
JDBC ➔ Hibernate XML ➔ Hibernate Annotations ➔ JPA ➔ Spring Data JPA
```

### Why Spring Data JPA?
- **Zero Boilerplate Implementation:** Automatically generates repository CRUD implementations at runtime based on interface definitions (`JpaRepository<Entity, ID>`).
- **Derived Query Methods:** Generates SQL queries automatically from method naming conventions (e.g., `findByNameContaining(String name)`).
- **Declarative Transactions:** Simple `@Transactional` annotation manages session boundaries, commits, and rollbacks.
- **Built-in Pagination & Sorting:** Out-of-the-box support for `Pageable` and `Sort` interfaces.

---

## 3. Core Objects of the Hibernate Framework

1. **`SessionFactory`**: A thread-safe, immutable cache of compiled mappings for a single database. Used to open `Session` instances.
2. **`Session`**: A single-threaded, short-lived object representing a conversation between the Java application and the database. Holds the first-level cache.
3. **`Transaction`**: Abstracts database transactions (JDBC or JTA), providing methods like `begin()`, `commit()`, and `rollback()`.
4. **`TransactionFactory`**: A factory for producing `Transaction` instances based on environment configuration.
5. **`ConnectionProvider`**: A factory for JDBC connections (manages connection pooling like HikariCP).

## 4. Hibernate XML Configuration vs. Annotation Configuration

| Feature | XML Configuration | Annotation Configuration |
| :--- | :--- | :--- |
| **Mapping File** | Requires separate `.hbm.xml` files. | Annotations directly inside `.java` entity files. |
| **Readability** | Mappings are separate from source code. | Highly readable and co-located with domain fields. |
| **Configuration File** | `hibernate.cfg.xml` lists mapping files. | `hibernate.cfg.xml` lists annotated classes (`<mapping class="..."/>`). |
| **Key Annotations** | N/A | `@Entity`, `@Table`, `@Id`, `@Column`, `@GeneratedValue`. |

## 5. Difference Between JPA, Hibernate, and Spring Data JPA

| Technology | Type | Description |
| :--- | :--- | :--- |
| **JPA (Java Persistence API)** | **Specification** (JSR 338) | Defines standard interfaces & annotations (`javax.persistence`). No concrete code implementation. |
| **Hibernate** | **ORM Implementation** | Fully-featured ORM tool implementing the JPA specification. Performs actual database operations. |
| **Spring Data JPA** | **Abstraction Layer** | Sits on top of JPA providers (Hibernate) to eliminate repository boilerplate code. |

## 6. Hibernate `ddl-auto` Configurations & DML Operations

### `spring.jpa.hibernate.ddl-auto` Options:
- **`validate`**: Validates schema against entity mappings; throws an exception if mismatch occurs.
- **`update`**: Updates the existing database schema without dropping tables.
- **`create`**: Drops existing tables and creates new tables upon startup.
- **`create-drop`**: Creates tables upon startup and drops them when `SessionFactory` closes.

### DML Operations with `JpaRepository`:
- **`save(entity)`**: Inserts a new record or updates an existing record.
- **`findById(id)`**: Retrieves an entity wrapped in `Optional<T>`.
- **`deleteById(id)`**: Deletes an entity record by its primary key.
- **Query Methods**: Custom queries automatically generated by method names (e.g., `findByNameContaining(String partialName)`).
